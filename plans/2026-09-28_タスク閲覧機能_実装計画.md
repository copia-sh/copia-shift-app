# タスク閲覧機能 実装計画

作成日: 2026-09-28
対象リポジトリ: `copia-sh/copia-shift-app`（branch `main`）

> **2026-09-29 追記：** 閲覧に加えて、進捗の更新（ステータス・状況メモ・成果物）をアプリから即時にシートへ書き込めるようにした。
> Worker の `POST /tasks/update` が本人と在籍を確かめて書き込み、取り込み直す。詳細は `worker/README.md`「タスク進捗の更新」。

## 目的

シフトアプリから、チームのタスク（単発タスク・定例業務）を**閲覧**できるようにする。
正本は今まで通りGoogleスプレッドシート「スタダチーム_タスク表」とし、アプリでは編集しない。
Slack → タスク表の更新運用（task-board-update / Codex定期実行）はそのまま使える。

## 方針

```
スタダチーム_タスク表 ──(Worker Cron: Sheets API 読み取り)──▶ Firestore
  タスク一覧 / 定例業務                                    groups/{gid}/taskBoard/current（1ドキュメント）
                                                                   │
                                                     アプリ（onSnapshot で閲覧のみ）
```

- **1ドキュメントに全タスクを入れる。** 画面を開くたびの読み取りが1回で済み、Firestore無料枠に影響しない
  （タスクは数十件なので1MB上限にも余裕がある）。
- **内容が変わったときだけ書き込む。** 前回の内容のハッシュと比べ、同じならスキップする。
- **アプリはシートの列名に依存しない。** Workerがヘッダー名で列を探して正規化した形で保存するため、
  列の追加・並べ替えがあっても壊れにくい（必須列が見つからなければ同期を失敗させて気づけるようにする）。

### 1. データ形（`taskBoard/current`）

```ts
interface TaskBoard {
  syncedAt: number;        // 同期時刻
  sourceUrl: string;       // シートへのリンク（編集はここから）
  tasks: BoardTask[];      // タスク一覧
  routines: BoardRoutine[];// 定例業務
}
interface BoardTask {
  no: string; title: string; purpose: string; assignees: string[]; // 「田村・佐藤・曽根（共同）」を分解
  due: string; priority: string; status: string; memo: string; deliverable: string; phase: string;
}
interface BoardRoutine {
  frequency: string; title: string; purpose: string; assignees: string[]; status: string; memo: string; deliverable: string;
}
```

担当者名はシートの表記（「田村」など）のまま持ち、アプリ側でメンバーの `displayName` と照合して「自分の担当」を判定する。
照合は Worker の既存 `memberName.ts` と同じ正規化（姓だけ・空白除去）を使う。

### 4. 設定値

- `TASK_SYNC_ENABLED`（vars, 既定 `"false"`）
- `TASK_BOARD_SPREADSHEET_ID`（secret。シフト同期と同じ理由で vars に置かない）
- 対象グループは既存の `AGENT_GROUP_ID` を使う
- 事前作業: サービスアカウントに「スタダチーム_タスク表」を**閲覧者**で共有する
- Cron は既存の5分ごとの実行の中で、15分に1回だけタスク同期を走らせる（Cron式は増やさない）

### 5. ルール

```
match /taskBoard/{docId} {
  allow read: if isMember(gid);
  allow write: if false;   // Worker はサービスアカウントなのでルールの対象外
}
```

### 7. 画面

- 最上位の画面を「シフト」「タスク」の2つにする（`App.tsx` に `screen: "shifts" | "tasks"` を持つ）。
  既存のタブ（シフトを見る / 希望を入力 / 確定・調整）はシフト画面の中にそのまま残す
- PC: ヘッダーに「シフト｜タスク」の切り替えボタンを1つ追加
- スマホ: 画面下部に固定フッターを置き、「シフト｜タスク」の左右つながりボタンで切り替える
  （`safe-area-inset-bottom` 対応、44px以上。複数選択バー・編集シートとの重なりはデザインに従う）
- 選んだ画面はURLのハッシュ（`#tasks`）に持ち、再読み込みやブラウザの戻るで保てるようにする
- タスク画面では、日付移動と一覧・月・週の切り替えを出さない
- 上部: 「自分の担当 / 全員」の切り替え、最終同期時刻、「シートで編集」リンク
- 「定例業務」「タスク」の2セクション。各カードに No・タスク名・担当・ステータス（色付きバッジ）・期限・優先度
- タップで状況メモ・成果物（URLはリンク化）・背景・目的を展開
- 同期前（ドキュメント未作成）のときは「まだ同期されていません」を表示
- スマホ幅（既存 `responsiveLayout.ts` の基準）で1列表示

## 対象外（今回やらない）

- アプリからの編集・ステータス変更
- シフト画面の日付セルへのタスク表示（出社日に担当タスクを出す等）は、閲覧機能が定着してから検討

## リリース手順

1. ルールをデプロイ（`firebase deploy --only firestore:rules`）
2. サービスアカウントへシートを閲覧共有 → `TASK_BOARD_SPREADSHEET_ID` を secret 登録
3. `TASK_SYNC_ENABLED="true"` で Worker をデプロイし、初回同期を確認
4. アプリをビルド・デプロイ（GitHub Pages）

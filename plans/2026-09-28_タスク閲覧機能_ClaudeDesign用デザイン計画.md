# タスク閲覧機能 Claude Design 用デザイン計画

作成日: 2026-09-28
用途: Claude Design でUIを設計するときの指示書（人が Claude Design に渡す前提）
対象: `copia-shift-app` にタスク閲覧画面を追加する
実装計画: `plans/2026-09-28_タスク閲覧機能_実装計画.md`
前提: 既存のトークン（`src/index.css` の `:root`）と段階2Aの Dialog / Sheet の型を使う

---

## 0. この機能は何か（30秒）

シフトアプリに、チームの**タスク**を見る画面を足す。タスクの正本はGoogleスプレッドシートで、アプリは**閲覧専用**。
編集はシートで行う（Slackの内容をAIがシートへ反映する運用があるため）。アプリは15分ごとにシートの内容を取り込む。

チームの業務は「Zoomの自習室で会員の質問に答え、AIを使いこなせるよう支援する」こと。インターン生3人（田村・佐藤・曽根）と担当社員（赤間）が使う。

| 利用者 | 最初に知りたいこと |
|---|---|
| メンバー | 自分の担当タスクは何か、次に何をやるか |
| リーダー・管理者 | 誰が何を持っているか、担当が決まっていないもの、止まっているもの |

**編集できる見た目を作らないこと。** 入力欄・チェックボックス・ドラッグ・ステータス変更のプルダウンは置かない。
変えたいときの入口は「シートで編集」リンクの1つだけ。

## 1. 作ってほしいもの（アートボード一覧）

### PC（幅1280px）

0. **P0 ヘッダーの切り替えボタン** — シフト画面・タスク画面それぞれでヘッダーに「シフト｜タスク」を置いた状態。
1. **P1 タスク一覧（全員）** — 定例業務とタスクの2セクション。
2. **P2 タスク一覧（自分の担当）** — 「自分」に切り替えた状態。自分の担当が0件のセクションの見せ方も含める。
3. **P3 タスク詳細** — 1件を開いた状態（右の詳細パネル。シフト画面の詳細パネルと同じ位置・型）。
4. **P4 状態バリエーション** — 読み込み中 / まだ同期されていない / 同期が古い（1時間以上前）/ 権限エラー / 0件。

### スマートフォン（幅375px）

5. **M1 タスク一覧** — 1列のカード。上部に「自分｜全員」、下部に固定フッター「シフト｜タスク」（タスクが選択状態）。
6. **M2 タスク詳細（シート）** — 下からせり上がるシート（段階2Aの Sheet の型）。フッターとの重なり方も示す。
7. **M3 シフト画面のフッター** — 既存の月ビューにフッター（シフトが選択状態）を足した状態と、複数選択バーが出ているときの状態。

## 2. 画面の置き場所

アプリの最上位に「シフト」と「タスク」の2画面を置き、行き来する切り替えを足す。
既存のタブ `[シフトを見る] [希望を入力] [確定・調整 ※権限あり]` は**シフト画面の中のタブ**のまま変えない。

### PC：ヘッダーに切り替えボタンを1つ

- ヘッダー（グループ名の並び）に **「シフト｜タスク」の切り替えボタンを1つ**追加する。
- 左右がつながった2択のボタン（セグメント）。今いる画面が選択状態。
- 置き場所はグループ名の右隣を基本案とし、別案があれば出してほしい。

### スマートフォン：フッターに切り替えボタン

- 画面下部に固定のフッターを置き、**「シフト」と「タスク」が左右につながったボタン**で行き来する（左＝シフト、右＝タスク）。
- ヘッダーには切り替えを出さない（PCとスマホで入口を1つずつにする）。
- `safe-area-inset-bottom` を考慮し、ボタンの高さは44px以上。
- シフト画面で下部に出る**複数選択のバー**・**編集シート**とぶつからないこと。重なり方（フッターの上に積む／選択中はフッターを隠す など）の案を出してほしい。
- フッターの高さぶん、本文の最下部が隠れないようにする。

### タスク画面で出さないもの

タスクは日付に縛られないので、日付の移動（前へ・次へ・今日）、一覧・月・週の切り替え、シフト画面のタブは出さない。

## 3. 表示する情報

### タスク（単発）

| 項目 | 一覧に出す | 詳細に出す | 備考 |
|---|---|---|---|
| No | ○ | ○ | 1〜の連番 |
| タスク内容 | ○ | ○ | 30〜50字が多い。一覧では2行まで、詳細では全文 |
| 担当 | ○ | ○ | 複数人あり。「未定」もある |
| 期限目安 | ○ | ○ | 「随時（早期）」「平日中」「来月」など**文字列**。日付とは限らない |
| 優先度 | ○ | ○ | 最重要 / 高 / 中 / 低 |
| ステータス | ○ | ○ | 下の表 |
| 背景・目的 | | ○ | |
| 状況メモ | | ○ | 長い（200〜400字）。日付付きの追記が続く形式 |
| 最新の成果物 | | ○ | ファイル名またはURL。URLはリンクにする |
| フェーズ | | ○ | 補足扱い |

### 定例業務

頻度（「毎週」「毎月（20日まで）」「定期（平日夜・休日昼）」など）／タスク内容／担当／ステータス／目的・状況メモ・成果物（詳細のみ）。

### ステータスの色（案）

| ステータス | 意味 | 色の方向 |
|---|---|---|
| 未着手 | まだ手を付けていない | 灰 |
| 検討中・未整備 | 方法を決めている段階 | 橙（`--c-orange`） |
| 進行中・練習中 | 作業中 | 青（`--c-blue`） |
| 運用中 | 定例として回っている | 青緑（`--c-teal`） |
| 完了 | 終わった（通常は一覧に出ない） | 緑または灰 |

色だけで区別しないこと（必ず文字のバッジにする）。

## 4. 振る舞い

- **自分｜全員**: 既定は「自分」。「自分」はログイン中メンバーの表示名とシートの担当者名を照合して判定する。
  共同担当（「田村・佐藤・曽根（共同）」）は全員の担当として扱う。
- **担当未定**: 「全員」表示のとき、担当が「未定」のタスクが分かるようにする（リーダーが振り分けるため）。
- **ステータスで絞り込み**: 複数選択。既定は全部。
- **並び順**: シートの順番（No順）。優先度で並べ替えはしない。
- **最終同期時刻**: 常に表示。1時間以上更新がなければ注意表示（同期が止まっている可能性）。
- **シートで編集**: 新しいタブでスプレッドシートを開く。
- 詳細を開いた状態でも一覧の位置を保つ（閉じたら元のスクロール位置）。

## 6. 守ってほしいこと

- 既存トークンを使う（色 `--c-*`、行高 `--h-row` など）。新しい色を足す場合は理由を書く。
- 文字サイズ: 本文14〜16px、補足12px。これより小さくしない。
- タップ対象は44pxを目標にする。
- 長い日本語（状況メモ）を詰め込まない。一覧では出さず、詳細で読みやすい行間にする。
- 担当者の表示は、シフト画面のメンバー色（丸いアイコン）と合わせてよい。シートの名前がメンバーに一致しない場合（「全員（毎月入力）」など）は文字のまま出す。

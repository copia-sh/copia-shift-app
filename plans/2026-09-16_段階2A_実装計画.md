## 1. `shiftTarget`：シフトを登録しないメンバー

社員のように希望を出さない人を、在籍のまま「シフト表に出さない・登録もしない」状態にします。属性タグ（絞り込み用）とは別の設定です。

**データ**
- `Member` に `shiftTarget: boolean` を追加（`types.ts`）。**既定 true**。
- 読み出し時に既定を埋める: `subscribeToMembers` の map で `shiftTarget: data.shiftTarget ?? true`。既存ドキュメントの移行は不要。
- 更新関数 `updateMemberShiftTarget(groupId, memberId, shiftTarget)` を `firebase/members.ts` に追加（既存 `updateMemberActive` と同じ形）。
- Firestore ルール: `shiftTarget` の更新は admin のみ。`active` と同じ扱いにする。

**派生値（1か所に置く）**
```ts
// types.ts
export function shiftTargetMembers(members: Member[]): Member[] {
  return members.filter((m) => m.active && m.shiftTarget);
}
```
シフト表・希望入力・集計は必ずこの関数を通します。`active` だけで絞っている箇所を洗い出して置き換えます。

**UI（C2 アートボード）**
- `MemberAdmin.tsx` の各行に「対象／対象外」トグル（角丸9999px・高さ34px、対象時は `border-[#248DD4] bg-[#D1E9F9] text-[#0863A0]`）。
- 補足文: 「対象外にすると、一覧・月・週のどのビューにも行が出ず、希望入力タブもその人には出ません。」
- 自分を対象外にはできる（管理者が自分で希望を出さない運用があるため）が、確認ダイアログを出す。
- 過去に登録済みの枠は消さない。書き出し（`ExportDialog`）と履歴には残す。
  - ~~既定では書き出し対象からも外し、「シフト対象外のメンバーを含める」チェックを追加する。~~
    **見送り（2026-09-16 決定）**: 現在の書き出しはログイン中の本人のシフトだけを対象にしているため、
    他人を含める・含めないという選択肢が成り立たない。書き出しをグループ全員ぶんへ広げる要件が
    出てきたときに、改めて設計する。

**影響範囲チェックリスト**
- シフト表の行（3ビュー）
- 「希望を入力」タブの対象者セレクト
- 月ビューの人数要約・未回答カウント
- 案内バーの「未提出 n人」
- iCal（`utils/ical.ts`）と共有リンク（`shareLinks`）: 対象外の既存枠は出す・新規は作らせない
  （どちらも本人分だけを扱うため、シフト対象の設定による分岐は不要）

## 3. 絞り込みの拡張

`MemberFilter.tsx` に足すもの（既存の 全員／自分／属性チップ は維持）。

- **氏名検索**: 高さ34px・幅180px の input。`displayName.includes(query)`（正規化は trim のみ）。`aria-label="氏名で絞り込む"`。
- **属性チップに人数**: 既存の `attributeCounts` をそのまま使う。
- **「対象外を表示」トグル**: 既定オフ。オンで `shiftTarget === false` の在籍メンバーも行に出す。
- **表示件数の表記**: 「表示 n人／シフト対象外 m人」。既存の「表示対象（n人）」を置き換え、3ビュー共通のヘッダー値としてこの1か所から配る。
- **0件のとき**（P1 のパネル）: 本体に説明を出す。属性が「社員」だけのときは「「社員」はシフト対象外に設定されているため、この表には出ません。」＋「対象外を表示する」「条件を解除」の2ボタン。それ以外は「条件に合うメンバーがいません。」
- 絞り込み状態は `localStorage`（グループIDごと）に保存し、再訪時に復元。

## 4. I-02 「見る」と「変える」を分ける

**やめること**
- セルタップでの種別循環（`cycleKeys` による即時トグル）と即保存。`cycleKeys` は「編集フォーム内の種別ボタンの並び順」としてのみ残す。

**入れること**
- セルタップ → `selection = { date, memberId }` を立てて詳細を開く。PC は右パネル（幅360px）、`< 1024px` は下からのシート。
- 詳細（P4）: 日付・氏名（全文）・時間枠一覧（記号＋時刻14px＋状態バッジ）・履歴・フッターの「編集」。
- 編集（P5）は詳細内の「編集」から開始。`draft` を state に持ち、保存まで Firestore に書かない。保存後に詳細へ戻る。
- 空欄セル → 日付が入った空の編集フォームを開く（保存はしない）。
- 編集できない枠も同じ濃さで読める。不透明度は下げない。理由を1文で書く（他人の枠／確定済み／シフト対象外の3種）。
- 無効な「編集」ボタンは消さずに `disabled` ＋ `title` に理由。

**新規ファイル**
- `src/components/ShiftDetailPanel.tsx` — 閲覧。props: `date`, `member`, `shifts`, `canEdit`, `lockReason`, `onEdit`, `onClose`。
- `src/components/ShiftEditForm.tsx` — 編集。props: `draft`, `maxSegments`, `types`, `onChange`, `onSave`, `onCancel`, `saving`, `error`。
- 既存の `SegmentEditor.tsx` は時間枠の行編集として内部で再利用する。

**保存**
- 保存中は入力を `disabled`、ボタンは「保存中…」。
- 失敗は**フォームの中**（ボタンの上）に `border-[#F0C7C7] bg-[#FDF1F1]` のブロックで出す。`draft` は保持。主画面のトーストには出さない。

## 8. 手数を減らす（I-02 の副作用対策）

タップ＝詳細にすると入力の手数が増えるため、同時に入れます。

- **よく使う型**: 自分の直近3か月で最多の組み合わせを「平日9-18」などの名前で保存。編集フォーム最下部に常設、1タップで種別と時刻を埋める。保存先は `groups/{id}/members/{id}/templates`。
- **複数日にまとめて適用**: 同じ入口から「適用先の日を選ぶ」→ カレンダーで複数日をタップ → 保存1回。確定済み・対象外は自動で除外し、除外件数を結果に出す。
- **先週の同じ曜日をコピー**: 空欄セルから開いたフォームの先頭候補。
- **範囲選択（PC・P6）**: ドラッグまたは Shift＋クリックで日×人を選択。下部バーに「3日・2人・5枠を選択中」＋「種別をまとめて変更／時間をまとめて変更／まとめて編集／選択解除」。編集できない枠は対象から外し、その旨を小さく書く。
- 新規 `src/utils/applyTemplate.ts` に「テンプレート×対象日→書き込む枠の配列」の純粋関数を置き、UIから切り離してテストする。

## 10. 受け入れ条件（デザイン確認と同じ観点）

- 1人 / 6人 / 12人 / 30人で破綻しない。30人の月ビューは要約が既定。
- 氏名2文字と6文字以上が混在しても崩れない。詳細は全文。
- 6種別＋却下が凡例と入力欄に収まる。
- 同じ人の同じ日に2枠・6枠あるとき、一覧（展開）・月（＋n人→詳細）・週（＋n枠→詳細）のいずれでも全部たどれる。
- 375 / 390 / 768 / 1280px。横スクロールはテーブルの内側だけ。
- 6状態を区別して描ける。
- 補足も12px以上。時刻を8pxにしない。
- グレースケールでも 確定・希望・不可・未回答 が区別できる。
- **シフト対象外のメンバーが、一覧・月・週・希望入力・人数要約・案内バーのどこにも出ない**（「対象外を表示」がオフのとき）。
- Escape・Tab循環・フォーカス復帰が全ダイアログで同じ挙動。
